## 4、OOP的三大特征

### 4.1、封装

#### 4.1.1、基本介绍

封装就是 把抽象出来的数据（属性）和 对数据的操作（方法）封装到一起，数据被保护在内部，程序的其他部分只有通过被授权的操作才能对数据进行操作。



#### 4.1.2、为什么要进行封装

A、对数据进行封装能够==隐藏实现的细节;==

B、对数据进行封装能够==对数据进行有效性验证==。

​     如果直接使用person.age，用户可以赋值任意的数据，如：person.age = -1;无法保证数据的有效性。



#### 4.1.3、封装的实现步骤

```java
A、对数据(属性)进行私有化设置，让本类的外部不能直接修改属性;
B、提供一个公共的setXXX方法，用于对属性进行修改(对数据进行验证赋值);
    public void setXXX(类型 参数名) {
        //加入数据验证的业务逻辑
        属性 = 参数名;
    }
C、提供一个公共的getXXX方法，用于获取属性的值。
```

```java
    }

    public double getBalance() {
        return balance;
    }

    public void setBalance(double balance) {
        if (balance > 0) {
            this.balance = balance;
        } else {
            System.out.println("余额必须大于0");
            this.balance = 0;
        }
    }

    public String getPassWord() {
        return passWord;
    }

    public void setPassWord(String passWord) {
        if (passWord.length() == 6) {
            this.passWord = passWord;
        } else {
            System.out.print("密码长度必须是6位，生成默认密码");
            this.passWord = "000000";
            System.out.println();
        }
    }

    public void info() {
        System.out.println("名字：" + name + " 密码：" + passWord + " 余额：" + balance);
    }
}
```

### 4.2、继承

#### 4.2.1、基本介绍

继承可以==解决代码复用性问题==，==当多个类存在相同的属性（成员变量）和 方法 时==，可以从这些类中抽象出父类。

在父类中定义这些相同的属性和方法，所有的子类不需要再重新定义这些属性和方法，只需要通过extends来声明继承父类即可使用这些属性和方法。



#### 4.2.2、继承示意图

#### 4.2.3、继承的基本语法

```java
class 子类 extends 父类 {
    .....
}
-----------------------------
A、子类会自动拥有父类的属性和方法;
B、父类 又叫 超类、基类;
C、子类 又叫 派生类。
```



#### 4.2.4、继承的使用细节

A、子类 继承了 父类所有的 属性和方法，但 ==私有的属性和方法== ==不能直接被子类访问到==(因为子类与父类不同类)，可以通过父类提供的公共方法去调用；

B、子类==必须调用父类的构造器==，完成==父类的初始化==（子类构造器中隐藏了一句super()，会默认去调用父类的无参构造器）；

C、当创建子类对象时，不管使用子类的哪个构造器，都会 默认去 调用父类的无参构造器super()；

​	如果父类没有提供无参构造器，则在子类的构造器中，==必须使用 super(参数列表); 去指定调用父类的哪个构造器==，完成对父类属性的初始化，否则，编译不会

​	通过。

D、super在使用时，必须放在构造器的第一行;

E、super() 和 this() 都只能放在构造器的第一行，因此不能共同存在同一构造器中。

F、Java中所有类都是Object类的子类，Object类是所有类的父类。

G、父类构造器的调用不限于直接父类，将一直向上追溯到Object类（顶级父类）;

H、子类最多只能继承一个父类，即：Java是单继承机制;

I、继承不能滥用，子类和父类之间必须满足 is - a 的关系。



#### 4.2.5、子类创建时的内存布局



```java

```

```java
class Test {
    public static void main(String[] args) {
        //分析创建一个子类，Son对象时的内存布局
        Son son = new Son();
        
        //1、输出son.name，会按照查找关系来确定返回信息
        //(1)、首先会看子类是否有该属性，如果子类有该属性，并且可以访问，则返回信息;
        //(2)、如果子类没有该属性，就会去看父类有没有这个属性，如果父类有该属性，并且可以访问，则返回信息；
        //     如果父类的属性此时不能访问则会报错(可以提供一个公共的方法来访问)；
        //(3)、如果父类也没有该属性，则会继续找上级父类，直到Object类。
        System.out.println(son.name); //大头儿子
        System.out.println(son.age);  //39
        System.out.println(son.hobby); //大头爷爷
    }
}
```

A、首先会加载类信息，确定类的继承关系，加载顺序为：Object ---> GrandPa ---> Father ---> Son；

B、然后会在堆中给Son对象开辟一段空间，并完成属性的初始化(引用数据类型放在方法区的常量池中，基本数据类型直接存放在堆中)；

C、在进行属性初始化时，会给父类中每个属性信息都进行初始化(重名不影响)；

D、完成属性初始化后，会将Son对象在堆中的地址返回到栈中的Son对象引用。

#### 4.2.6、继承课堂练习

```java
class A {
    A() {
        System.out.println("a")
    }
    
    A(String name) {
        System.out.println("a name");
    }
}

class B extend A {
    B() {
        this("abc");
        System.out.println("b")
    }
    
    B(String name) {
        System.out.println("b name");
    }
}
```

==在main()中：B b = new B(); 的输出结果是什么？==

(1)、首先会进入B类的无参构造器，执行 this(""abc); 此时会去执行B类的有参构造器

(2)、在B类的有参构造器中，隐藏了super()，去调用父类A的无参构造器，因此会先输出：a

(3)、执行完父类A的无参构造器后，会返回B类的有参构造器，继续向下执行，输出：b name

(4)、执行完B类的有参构造器后，会返回B类的无参构造器，继续向下执行，输出：b

#### 4.3.2、基本介绍

方法 或 对象 具有多种形态，多态是建立在 ==封装== 和 ==继承== 的基础上。



#### 4.3.3、多态 和 动态绑定机制

##### #1、什么是多态

​    多态是面向对象的三大特征之一，他是建立在封装和继承的基础之上的。
​    具体表现为：==方法的多态==  和  ==对象的多态==

​	==方法的多态==体现在：==重写== 和 ==重载（编译的时候就已经确定要调用的方法了，不算）== 上，可以调用相同的方法名实现不同功能。

​	==对象的多态==体现在：==父类的引用可以指向子类的对象==，在 ==运行时== 会 ==通过动态绑定机制（对象的运行类型）调用不同类的方法==，实现不同功能



##### #2、什么是动态绑定机制

​    在==调用对象的方法==时，会 ==跟对象的运行类型进行绑定==；

​    在==调用对象的属性==时，没有动态绑定机制，属性在编译阶段就已经确定了(看编译类型)。



##### #3、动态绑定机制 和 多态 的区别

动态绑定是实现多态的一种机制，在方法调用的过程中，由 JVM 根据对象的 运行类型 来决定方法的调用。

多态是一个更广泛的概念，同一个操作，在不同对象上可能表现出不同的行为。



#### 4.3.4、多态的具体表现

##### #1、方法的多态

​      ==方法的重载== 和 ==方法的重写== 就体现了多态;

##### #2、对象的多态

 对象的 编译类型 和 运行类型 可以不一致;

​        父类的引用 指向 子类的对象 如：==Animal animal = new Dog();==    编译类型Animal，运行类型DOg

   编译类型在定义对象的时候就确定了，不能改变;

   运行类型是可以变化的：

​        如：animal = new Cat();    animal的运行类型变成了Cat，编译类型仍然是Animal

   编译类型看 = 的左边，运行类型看 = 的右边。



#### 4.3.5、多态的向上转型

A、多态的前提：两个类存在继承关系;

B、本质：向上转型：==父类的引用 指向 子类的对象==;

​      可以调用父类中的所有成员(须遵守访问权限)，但不能调用子类中的特有成员;

​      因为在编译阶段，能调用哪些成员，是由编译类型来决定的;

​      最终运行效果要看子类的具体实现，在调用方法的时候，==会先从子类开始查找方法==，然后调用（==成员方法：运行时绑定==）。

​      在调用成员变量时，会调用父类的成员变量（==成员变量：编译时绑定==）。

C、特点：编译类型看左边，运行类型看右边。



#### 4.3.6、多态的向下转型

A、子类类型 引用名 = (子类类型)父类引用;    如：Cat cat = (Cat)animal；

B、==只能强转父类的引用==，不能强转父类的对象；

C、要求：父类的引用 指向 当前目标类型对象；

D、当向下转型后，就==可以调用子类类型的所有成员==了。



#### 4.3.7、动态绑定机制案例

​    A、当调用对象方法时，该方法会 和  ==对象的运行类型== 绑定;

​    B、当调用对象属性时，没有动态绑定机制，哪里声明，哪里使用。

​       属性看编译类型是通过一个对象引用来调用属性时，是看编译类型。如：A a = new B(); a.name; 此时调用的是父类A中的属性

## 5、super关键字

### 5.1、基本介绍

super代表父类的引用，用于访问父类的属性、方法 和 构造器。

A、super.属性名：访问父类的属性，但不能访问父类的私有属性;

B、super.方法名()：访问父类的方法。

C、super()：访问父类构造器。



### 5.2、super关键字的使用细节

A、调用父类的构造器，可以使得程序分工明确（父类属性 由 父类构造器进行初始化，子类属性 由 子类构造器进行初始化）；

B、当子类中的成员（属性和方法） 与 父类中的成员（属性和方法）==重名==时，为了能够==访问父类的成员==，必须==使用super关键字==；

C、如果==没有重名==，可以使用super、this 或 属性/方法名 访问，会==先从本类开始查找==，

​      如果在查找过程中找到了但是private私有的，会报错(私有访问权限)，没找到会继续查找父类。

​      super是先去查找直接父类中有没有该成员，如果没有会继续向上查找，其他规则和this、属性/方法名访问规则相同。

## 6、方法的重写（Override）

### 6.1、基本介绍

方法的重写就是子类的某个方法，和父类的某个方法相同（方法名、参数、返回类型必须和父类相同 或 是父类返回类型的子类类型），就构成了方法的重写。

```java
class Animal {
    public Animal getAnimal() {
        return new Animal();
    }
}

class Dog extends Animal {
    @Override
    public Dog getAnimal() {  // 返回值类型是 Dog，而不是 Animal，也构成了方法的重写
        return new Dog();
    }
}
```



### 6.2、方法重写的使用细节

A、子类的 方法名、形参列表（类型、个数、顺序)）要求 和父类方法完全一致；

B、子类方法的返回值类型 ==要求和 父类方法的返回值类型 相同==，==或是 父类返回值类型的子类==；

   如：父类返回值类型是Object，子类方法返回值类型是String

   public Object getInfo(){...}    public String getInfo(){...}

C、子类方法不能缩小父类的访问权限;

   父类是protected的访问权限，子类必须是public、protected访问权限

   父类：protected void eat(){...}    子类：public void eat(){...}

### 7.5、finalize方法

#### 7.5.1、基本介绍

A、当==对象被回收==时，系统==自动调用该对象的 finalize 方法==；

​      子类可以重写该方法，做一些释放资源（关闭数据库的连接、打开一个文件）的操作；

B、什么时候被回收：

​        当某个对象没有任何引用时，则 JVM 则认为这个对象是一个垃圾对象，就会使用垃圾回收机制来销毁该对象；

​        ==在销毁该对象前，会先调用finalize方法==。

C、垃圾回收机制的调用，是由系统来决定，也可以通过==System.gc()主动触发垃圾回收机制==。



#### 7.5.2、finalize使用案例

```java
package com.java.finalize_;

public class Finalize_ {
    public static void main(String[] args) {
        Car bmw = new Car("宝马");
        //1、将Car对象引用置为null，此时Car对象就是一个垃圾
        //2、垃圾回收器就会销毁这个对象(释放堆中Car对象的内存空间)
        //3、程序员可以重写finalize方法，写自己的业务逻辑代码(如：进行数据库的连接 或 打开某个文件)
        //   如果程序员不重写finalize方法，那么就会调用Object类中的finalize方法
        //4、此时Car对象引用为null，但JVM不会马上进行垃圾回收
        //   垃圾回收机制的调用是由系统来决定的（有GC垃圾回收算法）
        bmw = null;  
        
        //5、可以通过System.gc()来主动触发垃圾回收机制
        //   该方法也有可能不会触发垃圾回收机制，会有系统来决定(垃圾回收器可能正在忙 或 其他原因调用不了)
        //   可以使用：Thread.sleep(3000); 给垃圾回收器足够时间来回收资源
        //   Java 9之后建议：使用 java.lang.ref.Cleaner 或 try-with-resources 机制来管理资源
        System.gc();
        
        System.out.println("程序退出了...");
    }
```

```java
//删除房屋信息
public boolean delete(int delId) {
    //用于记录房屋信息在数组中的下标位置
    int index = -1;

    //1、首先通过房屋id来找到House[]对应的下标
    for (int i = 0; i < houseNum; i++) {
        //1.1、当用户输入的id号 与 数组下标 所对应的id号相同时，则将数组的下表记录下来，以便后续删除
        if (delId == houses[i].getId()) {
            index = i;
        }
    }

    //2、如果没有在数组中找到用户输入的房屋id号(即：index = -1; index没有被修改的情况下)
    if (index == -1) {
        return false;
    }

    //3.1、不开辟新的数组完成对数据的删除
    for (int i = index; i < houseNum - 1; i++) {
        //将要删除下标位置后面的数据依次往前移动，并将后面的位置置为null
        houses[i] = houses[i + 1];
        //houseNum--;
    }

    //把当前已经存在的房屋信息数据后面一个位置置为null
    houses[--houseNum] = null;

    return true;
}
```
